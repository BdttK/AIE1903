3. 传感器与时间结构（这是 nuScenes 最特别的设计）

┌───────────┬──────┬────────────────────┬──────────┬──────────┬───────────┐
│  传感器   │ 数量 │    分辨率/点数     │ 采集频率 │ 关键帧数 │ sweep 数  │
├───────────┼──────┼────────────────────┼──────────┼──────────┼───────────┤
│ 6 路相机  │    6 │ 1600×900 JPEG      │   ~12 Hz │   404/路 │ ~1,930/路 │
├───────────┼──────┼────────────────────┼──────────┼──────────┼───────────┤
│ LIDAR_TOP │    1 │ ~34,700 点，32 线  │    20 Hz │      404 │     3,531 │
├───────────┼──────┼────────────────────┼──────────┼──────────┼───────────┤
│ 5 路雷达  │    5 │ ~120 点，18 个字段 │   ~13 Hz │   404/路 │ ~2,250/路 │
└───────────┴──────┴────────────────────┴──────────┴──────────┴───────────┘

- keyframe（2 Hz，每 0.5 s）：12 个传感器全部同步，且只有关键帧有 3D 框标注。
- sweep：关键帧之间的高频原始帧，无标注，用于时序/运动估计。所以每个关键帧间隔内约有 9.7 帧 LiDAR、5.8 帧相机。

7. 格式细节 + 三个必知坑

1. LiDAR 是无头二进制。文件实际是 *.pcd.bin（元数据也这么写），内容是纯 float32 的 (N, 5) 数组：x, y, z, intensity(0–255), ring(0–31)。没有 PCD 文本头，必须这样读：
pc = np.fromfile(path, dtype=np.float32).reshape(-1, 5)
   官方 devkit 的 LidarPointCloud.from_file 会按 PCD 头解析，在这里会失败。雷达则是正常的 PCD（ASCII 头 + binary 数据，18 个字段）。
2. devkit 未安装（import nuscenes 失败）。如果要用官方 API，需要 pip install nuscenes-devkit，但 LiDAR 读取仍需按上面方式自己处理。
3. 文件名里嵌了本地时间（如 n015-2018-11-21-19-38-26+0800__CAM_FRONT__…jpg），而 sample.timestamp 是 UTC 微秒时间戳，两者不要混用。

最小上手代码（不依赖 devkit）：

import json, os, numpy as np
root = 'data/nuscenes_full'; ver = 'v1.0-mini'
L = lambda n: json.load(open(f'{root}/{ver}/{n}.json'))

sample = L('sample')[0]
frames = [d for d in L('sample_data') if d['sample_token'] == sample['token']]
for d in frames:
    print(d['filename'], d['is_key_frame'])

pc = np.fromfile(f"{root}/{frames[0]['filename']}", np.float32).reshape(-1, 5)  # LiDAR 帧

- BEV 可视化 / 点云浏览器：直接读 .pcd.bin + calibrated_sensor + ego_pose 做坐标变换，404 帧足够做出漂亮 demo，不涉及训练。
- 低光照失效研究：scene-1077/1094/1100 三个夜雨场景是现成的对照实验素材。
- 可行驶区域 / 占据栅格：LiDAR 点云 + 语义先验地图 PNG 就能算。
